# custom-robo-recomp

Static recompilation of Custom Robo (GameCube, GXCE01) to New 3DS.

## Rules

- **Never hand-port game logic.** All game code comes from main.dol through the
  translator. Only the SDK/hardware layer (GX, DVD, PAD, OS, AI/DSP, CARD,
  VI) is written by hand, in `runtime/`. If a fix means rewriting game
  behaviour, stop and ask: it means the runtime is wrong.
- **Oracle: Dolphin** running the same disc. A difference is a runtime bug.
- **Progress number:** boot stage reached (main loop -> logo -> title -> menu
  -> battle) and SDK functions replaced / total (`docs/sdk_functions.md`).

## Layout

- `tools/recomp/` PPC -> C translator (`recomp.py`, decoder `ppc.py`). Output to
  `gen/` (ignored): `f_XXXXXXXX()` per function, `sdk_stubs.c` (weak, empty),
  `functable.c` (`call_indirect`). Unknowns -> `docs/recomp_unknowns.md`.
- `runtime/ppc.h` CPU state + BE memory + FP/paired-single helpers (Dolphin
  semantics); `runtime/cpu.c` placeholders; `runtime/main.c` 3DS entry.
- `runtime/` 3DS replacements for SDK functions, one file per SDK module.
- `tools/` carried over: `dol.py` (xref/dis/func), `ghidra/decompile.ps1`,
  `extract_disc.py`, and asset decoders (`sound.py`, `tpl.py`, `font.py`,
  `bmg.py`, `gxtex.py`) for the runtime to reuse. `decomp_names.tsv` = known
  function names.
- Reference only, do not copy code from: `../custom-robo-3ds` (old
  reimplementation; its CLAUDE.md has format and address notes).

## Phases (one per session)

1. SDK inventory -> `docs/sdk_functions.md` (address, name, module).
2. Translator: all of main.dol compiles for ARM.
3. Stub runtime: every SDK call logs; boots to main loop on Citra.
4. DVD, PAD, OS -> reaches title screen in the log.
5. GX -> PICA200 graphics.
6. Audio.
7. Fix pass vs Dolphin.

## Build / test

```
python tools/extract_disc.py "<disc>.iso" data/extracted   # once (--sys-only: sys/ only)
PYTHONUTF8=1 python tools/recomp/recomp.py                   # -> gen/
(cd tools/recomp && PYTHONUTF8=1 python gen_sdk_log.py)      # after adding an sdk_* to runtime/
docker run --rm -v "C:/Users/Alexander/source/repos/custom-robo-recomp:/proj" -w /proj mkw3ds-build:2026-10-09 make
```
Citra: `tools/citra/autotest.ps1 -Fast -Shots 0` (title: add `-Pad '360 366 100; 450 456 100; 540 546 100; 630 636 100'`), never take desktop focus; log in
`build/cr_autotest.log`. Needs `main.dol`, `boot.bin`, `fst.bin` from `data/extracted/sys/` and the
`data/extracted/files/` tree copied to Citra's `user/sdmc/custom-robo/` (never commit them).
Windows: run Python with `PYTHONUTF8=1`.

## Token rules

- Mechanical sweeps (SDK signatures, function boundaries, call inventories,
  hot spots, first failure in a log) -> Sonnet/Haiku subagents; only
  conclusions come back.
- Check every name a subagent (or the doc) gives against the disassembly
  (`tools/dol.py dis 0x<addr> 0x<count>`, both args 0x-prefixed): 0x80144be4
  was listed as AXFreeVoice but is AXSetVoicePriority.
- Logs, not screenshots (a few at most, for visual checks vs Dolphin). Grep
  gen/ and decompiles, never dump them or whole functions.
- Git Bash: build with `MSYS_NO_PATHCONV=1`. `\n` in C strings and `\` in
  paths get mangled by python heredocs and sed: use Edit for those lines.
- One phase per session; this file carries the state.
- Never commit disc data or game code; `gen/` is generated from the user's disc.
