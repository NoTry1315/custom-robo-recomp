# Custom Robo Recomp v0.1.2 (source only)

Bug-fix release of the static recompilation of *Custom Robo* (GameCube, USA, GXCE01) for the New Nintendo 3DS.

**This release contains no game and no prebuilt `.3dsx`.** A build contains code translated from the game's `main.dol`, so no build is published here. You build your own from your own legally obtained disc; see the [build and installation guide](https://github.com/alexander-clawthorne/custom-robo-recomp/blob/v0.1.2/README.detailed.md#build).

## Fixed

**The 3D view no longer stays shifted after the HOME menu.** After returning from HOME, the scene could stay shifted up or down (it looked as if the camera had pitched) until the game was restarted.

- **Cause:** the stereo 3D shader input that offsets each eye is written directly, so citro3d did not send it again when the game resumed from HOME.
- **Fix:** it is now sent again after every resume. Details: [recomp_unknowns.md](https://github.com/alexander-clawthorne/custom-robo-recomp/blob/v0.1.2/docs/recomp_unknowns.md), section "Eye uniform after the HOME menu".
- **Checked:** in Citra. Not yet confirmed on hardware.

## New: a record of HOME transitions

Pressing HOME has twice crashed the whole 3DS (Luma3DS exception screen). The crash dump shows a panic inside HOME Menu itself, not in the game, and the cause is not found yet. To catch it next time, the game now writes every step of a HOME or sleep transition to `sdmc:/cr_suspend.log`, along with what its own threads were doing and how much memory is free. The file is written as it goes, so it survives a crash.

**If HOME crashes your 3DS,** please [open an issue](https://github.com/alexander-clawthorne/custom-robo-recomp/issues) and attach `sdmc:/cr_suspend.log`, the newest `sdmc:/luma/dumps/arm11/crash_dump_*.dmp` and `sdmc:/cr_autotest.log`.

Checked on a New 3DS: a scripted HOME, a real HOME, a resume and a Close all went through cleanly with the record on. The record costs nothing during play; during a HOME transition it only queues lines in memory, and a background thread writes them to the SD. Details: [recomp_unknowns.md](https://github.com/alexander-clawthorne/custom-robo-recomp/blob/v0.1.2/docs/recomp_unknowns.md), section "HOME Menu panic on HOME".

## What works

Playable on New 3DS hardware through the title, menus, campaign and Vs. battles, with sound, memory card saves, stereoscopic 3D, widescreen, the attract movie and the HOME button. Performance is unchanged from v0.1.0:

| Scene | New 3DS |
|---|---:|
| Title and menus | about 60 fps |
| Campaign | 59 fps |
| 1-v-1 battle | 57 fps (51 fps with 3D) |
| 2-v-2 battle | 47 fps |
| Attract movie | 44 fps (74% of its 30 fps) |

The game runs one logic step per frame, so scenes below 60 fps run in slow motion. Old 3DS models are untested.

## Known problems

- Pressing HOME has twice crashed the whole 3DS (see above; cause not found yet).
- 2-v-2 battles and stereoscopic scenes do not yet hold 60 fps.
- Some graphics are missing: EFB-to-texture copies, specular highlights; widescreen leaves some 2D at the 4:3 edges.
- In Citra only, the dark background behind dialogue text is sometimes missing; the 3DS draws it.
- SD-card stalls can still disturb music at the start of a song.

Full list: [Known problems](https://github.com/alexander-clawthorne/custom-robo-recomp/blob/v0.1.2/README.detailed.md#known-problems).

## What you need

- A New 3DS or New 2DS XL with custom firmware and the Homebrew Launcher.
- Your own *Custom Robo* USA disc (GXCE01) and a way to read its files.
- `sdmc:/3ds/dspfirm.cdc` dumped from your own 3DS (DSP1) for sound.
- devkitPro/devkitARM (or the Docker build image) and Python 3.
