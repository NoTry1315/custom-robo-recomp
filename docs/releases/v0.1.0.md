# Custom Robo Recomp v0.1.0 (source only)

First tagged release of the static recompilation of *Custom Robo* (GameCube, USA, GXCE01)
for the New Nintendo 3DS.

**This release contains no game and no prebuilt `.3dsx`.** A build contains code translated
from the game's `main.dol`, so no build is published here. You build your own from your own
legally obtained disc; see the
[build and installation guide](../../README.detailed.md#build).

## What works

Playable on New 3DS hardware through the title, menus, campaign and Vs. battles, with sound,
memory card saves, stereoscopic 3D, widescreen, the attract movie and the HOME button.

| Scene | New 3DS |
|---|---:|
| Title and menus | about 60 fps |
| Campaign | 59 fps |
| 1-v-1 battle | 57 fps (51 fps with 3D) |
| 2-v-2 battle | 47 fps |
| Attract movie | 44 fps (74% of its 30 fps) |

The game runs one logic step per frame, so scenes below 60 fps run in slow motion. Old 3DS
models are untested.

## Known problems

- 2-v-2 battles and stereoscopic scenes do not yet hold 60 fps.
- Some graphics are missing: EFB-to-texture copies, specular highlights; widescreen leaves
  some 2D at the 4:3 edges.
- One hardware run showed a story text box with missing letters, then a hang; not reproduced.
- SD-card stalls can still disturb music at the start of a song.

Full list: [Known problems](../../README.detailed.md#known-problems).

## What you need

- A New 3DS or New 2DS XL with custom firmware and the Homebrew Launcher.
- Your own *Custom Robo* USA disc (GXCE01) and a way to read its files.
- `sdmc:/3ds/dspfirm.cdc` dumped from your own 3DS (DSP1) for sound.
- devkitPro/devkitARM (or the Docker build image) and Python 3.

## How it was made

The game's logic is not rewritten: every line of game code comes from your disc and is
translated by `tools/recomp/recomp.py`. Only the GameCube SDK and hardware layer (graphics,
disc, controller, OS, audio, video, memory card) is written for the 3DS, in `runtime/`.
Dolphin running the same disc is the reference; changes are checked with deterministic
Citra replays (identical SDK-call, scene, input, framebuffer and audio logs) and measured on
real hardware ([performance record](../../docs/performance.md)).

AI tools (Claude Code) were used heavily for implementation, investigation, test tooling and
documentation; `CLAUDE.md` is the working log used with them. The maintainer makes the
decisions and checks the results in Citra and on hardware.
